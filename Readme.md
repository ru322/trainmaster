# Train Master

## 概要

- グリッド状のマップ
- ランダムに生成される駅を線路で結んで線路をどんどん大きくしていくゲーム
- インクリメンタルゲーム
- 駅と駅を線路で結ぶ
- 線路はグリッドに配置する
- 路線は複数の駅がある
- お客さんは駅に到着するたびに
  - お金を落としていく
- 全てにレベルの概念がある
  - 駅
    - お客さんが来る頻度
    - お客さんが落とすお金の量
    - お客さんの最大人数
    - ホーム長(長い列車は短いホームには停車できない)
  - 電車
    - 速度
    - 乗客の最大人数
    - 乗客の乗り降り速度
    - 1車両の人数
    - 両数
  - 路線
    - 1つの路線を走らせられる最大列車数
    - 新たな路線の作成
    - 魅力度
- 減らすことはできない
  - 駅の削除とか路線の削除とかは当然できない
  - 一度上げたレベルは下げることはできない
- 放置してお金を稼げばいっぱい稼げるがレベルアップのコストは指数関数的に増えていくので、放置してお金を稼ぐだけでは会社の規模は大きくならない
  - レベルアップで稼げる量は指数関数的に増える
- ありとあらゆるパラメータをレベルアップさせていって会社の規模を大きくしていく
  - 設備をレベルアップすると会社レベルがあがる
    - 会社レベルが無いと解放されない機能や一定以上レベルアップできない設備がある
    - これは1つの設備をレベルアップさせるだけでなくいろんな設備をレベルアップさせるためのストッパー
  - 最初は1円とかしか稼げないが、会社レベルが上がると1無量大数円とか稼げるようになる
- プレイヤーは鉄道会社の社長という設定
- 会社レベルで駅の数が増える
  - 駅の場所はランダムに生成される
  - 1つの駅に複数の路線が接続できる
  - 乗客は駅で生成されたときにランダムに目的地の駅が決まる
  - 乗客は電車の速度と路線の魅力度で経路を決める
  - 経路はあらかじめFloyd–WarshallやDijkstraやJohnsonやBellman–Fordで全ての駅について全ての駅までの最短経路を計算しておく
    - これで乗客毎に経路探索をする必要がなくなる
    - 経路更新は駅の追加や路線の追加があったときに行う
    - 駅や路線の数はたかが知れた数しか無ければ問題ない
- デザインは上から見下ろした視点
  - 2D
- 3Dはやらない
- 開発環境はLinux
  - 開発環境はキーボードで代用
- 最終的にはラズパイ3で動くようにする
  - SDカードに書き込んでラズパイを起動したらゲームが始まるようにする
  - キーボードかゲームパッドで操作できるようにする
- 子どもでも遊べるようにする
  - ルールは簡単にする
  - 説明(チュートリアル)を充実させる
  - 文章はわかりやすくする

## 転生システム

- `config/reincarnation.toml` で設定する
  - 転生できる累計収入・会社レベル
  - 転生で得る魂(soul)の式
  - 進化の段階(tier)の解放条件
  - 進化のノード(値段・最大レベル・前提・効果)
- ビルドにはこのファイルを埋め込む。`TM_REINCARNATION_FILE=/path/to/reincarnation.toml` で差し替えられる
- 会社のお金・駅・路線・列車は転生でやり直しになり、魂・解放した進化・転生回数だけが残る
- 進化の効果は運賃収入・お客さんの発生・強化の値段・線路の値段・転生で得る魂・転生後の所持金に効く

## 技術

- Buildroot
- SDL2
- rust
  - 必要に応じて C/C++ を使うが使わないほうが好ましい.使うなら最小限に
- Nix(`flake.nix` の `nix develop`。Rust 1.88.0・SDL2・Buildroot のホスト道具)
  - `nix develop` で devshell に入る。`rustc`/`cargo`/`SDL2`/`mise` がそろう
  - mise も devshell に入るので `mise run test` などはそのまま使える

## 備考

- イベント展示用のゲーム
  - 15分くらいで全ての機能を体験できるようにする
  - 1無量大数はイベントの間に稼げなくてOK
  - とりあえずライセンスは考えなくていい
- 開発環境はLinuxで試すのでクロスコンパイルする
- 設計段階で機能の分離やモジュールの結合度を考慮して設計する
- ビルドしたらimgファイルを作って raspberry pi imager でSDカードに書き込めるようにする
- 開発環境は mise を使う
- ビルドは CI/CD で自動化する(GitHub Actions)
- docsは gitginore する
